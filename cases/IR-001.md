# IR-001 | Detección y recuperación de una modificación de integridad en Linux

**Tipo:** ejercicio de respuesta a incidentes **simulado y autorizado**. **Estado:** ejercicio cerrado, con recuperación del contenido validada en endpoint y Wazuh. No hubo intrusión real confirmada, contención de un adversario ni erradicación de malware.

## 1. Objetivo

Comprobar si el SOC Lab permite investigar una alteración de un archivo controlado, correlacionar el estado del endpoint con alertas Wazuh FIM y revertir el contenido de manera segura. El alcance se limitó a `/opt/soclab-fim/ir-001-test.txt`.

## 2. Entorno y autorización

| Elemento | Estado observado |
|---|---|
| Origen de acceso | `SOC-Analyst-WS`, IP observada `10.50.10.100` |
| Destino | `LINUX-EP-01`, IP comprobada `10.50.20.21`, SSH puerto 22 accesible |
| Sistema operativo | Ubuntu 24.04.5 LTS, kernel `6.8.0-139-generic` |
| Agente | Wazuh `4.14.7`, ID `002`, servicio activo |
| Manager configurado | `10.50.10.10:1514/TCP` |
| FIM | `realtime=yes`, `report_changes=yes` para `/opt/soclab-fim`, mediante `agent.conf` centralizado |
| Directorio | Propietario `root:root`, permisos `755`, vacío al comenzar |
| Protección | Snapshot previo visible en VMware; restauración del snapshot **no probada** |

La configuración se **reutilizó**. No se instalaron herramientas, no se cambiaron reglas ni se alteró infraestructura global.

## 3. Paso 1 — Acceder y auditar el endpoint

Desde PowerShell en SOC-Analyst-WS se validó el acceso:

```powershell
Test-NetConnection 10.50.20.21 -Port 22
ssh linux@10.50.20.21
```

**Resultado:** `TcpTestSucceeded : True` y sesión SSH autenticada. En Linux se comprobaron identidad, interfaces, recursos, agente y permisos de `/opt/soclab-fim`:

```bash
hostname
ip -br addr
free -h
df -h /
systemctl is-active wazuh-agent
sudo ls -la /opt/soclab-fim
```

**Observado:** `linux-ep-01`, interfaz `ens33` con `10.50.20.21/24`; alrededor de 3,8 GiB RAM, 29 GB libres en `/`; agente `active`; directorio de pruebas inicialmente vacío. No se atribuye a estas comprobaciones una modificación de infraestructura.

## 4. Paso 2 — Confirmar que FIM monitoriza realmente la ruta

Se examinó el estado del servicio y los logs sin editar la configuración:

```bash
sudo grep -aEi 'connected to the server|syscheck' /var/ossec/logs/ossec.log | tail -50
sudo grep -aRin 'soclab-fim' /var/ossec/etc/ 2>/dev/null
```

**Hallazgos:** el log registró `Connected to the server ([10.50.10.10]:1514/tcp)`, `Directory set for real time monitoring: '/opt/soclab-fim'` y `Real-time file integrity monitoring started`. La ruta procedía de `/var/ossec/etc/shared/agent.conf`:

```xml
<directories check_all="yes" realtime="yes" report_changes="yes">/opt/soclab-fim</directories>
```

Una conexión TCP por sí sola no demuestra ingestión, pero posteriormente las alertas sí confirmaron que los cambios llegaron a Wazuh.

## 5. Paso 3 — Registrar el baseline

Antes del cambio se observó la ausencia del fichero y el estado del agente:

```bash
date -u --iso-8601=ns
sudo stat -c '%A %U:%G %n' /opt/soclab-fim
sudo test ! -e /opt/soclab-fim/ir-001-test.txt && echo 'Archivo ausente'
systemctl is-active wazuh-agent
```

**Resultado:** comprobación previa `2026-10-10T16:52:42,057973442+00:00`, fichero ausente, carpeta `root:root` con permisos `755` y agente activo. Se preparó una restauración **limitada al contenido de prueba**, sin restaurar la VM.

## 6. Paso 4 — Crear y modificar el archivo autorizado

El procedimiento ejecutado consistió en escribir una línea inicial, calcular el hash y añadir una línea ficticia:

```bash
FILE=/opt/soclab-fim/ir-001-test.txt
printf 'IR-001 baseline - authorized test\n' | sudo tee "$FILE" >/dev/null
sudo chmod 0644 "$FILE"
sudo sha256sum "$FILE"
printf 'IR-001 simulated unauthorized modification\n' | sudo tee -a "$FILE" >/dev/null
sudo sha256sum "$FILE"
```

| Propiedad | Archivo creado | Archivo modificado |
|---|---|---|
| Tamaño | 34 bytes | 77 bytes |
| SHA256 | `c75f1cdf6621fac32c7b712a5d2dc1937b7ce9cbbb5439925de0013aa6347988` | `f740ee5bb8732fb79dc3ef99b3c75027660480f41e655ca9c290cdeca9abfdef` |
| Marca de modificación de Linux | `16:53:23.430907435 +0000` | `16:53:23.564907424 +0000` |

La línea añadida representaba **solo** un cambio controlado, no un acceso no autorizado real.

## 7. Paso 5 — Buscar y analizar las alertas

Se consultó Wazuh Threat Hunting por el agente `LINUX-EP-01` (`002`) y la ruta exacta del archivo. Se retiraron filtros ajenos del agente Windows `001` para evitar búsquedas vacías o mal interpretadas.

| Etapa | Regla y nivel | ID de alerta | Dato clave |
|---|---|---|---|
| Archivo añadido | `554`, nivel 5 | `1791644001.430931` | `syscheck.event=added`, 34 bytes, SHA256 inicial |
| Integridad alterada | `550`, nivel 7 | `1791644001.431630` | `syscheck.event=modified`, 34 → 77 bytes, SHA256 inicial → modificado |
| Recuperación | `550`, nivel 7 | `1791645056.445431` | `syscheck.event=modified`, 77 → 34 bytes, SHA256 modificado → inicial |

**La segunda alerta** incluía el diff:

```diff
+ IR-001 simulated unauthorized modification
```

La regla 550 informó `T1565.001` (*Stored Data Manipulation*); representa el mapeo ATT&CK de la detección, no prueba actividad de un atacante. Un evento adicional `2902` sobre instalación de un paquete `dpkg` fue observado en las búsquedas y **no se incluyó** como evidencia del ejercicio.

## 8. Paso 6 — Determinación y respuesta

**Decisión:** actividad de prueba conocida y autorizada. No correspondía aislar el equipo, bloquear red o ejecutar contención de un atacante.

Se eligió **restaurar solamente el contenido del fichero**, comprobando antes que su SHA256 coincidía con el estado modificado esperado:

```bash
FILE=/opt/soclab-fim/ir-001-test.txt
sudo sha256sum "$FILE"
# Tras comprobar coincidencia con el SHA256 modificado esperado:
printf 'IR-001 baseline - authorized test\n' | sudo tee "$FILE" >/dev/null
sudo sha256sum "$FILE"
```

**Resultado verificado en Linux:** recuperación registrada en torno a `2026-10-10T17:10:57.966252554+00:00`, tamaño **34 bytes**, permisos `644`, usuario/grupo `root:root`, agente `active` y SHA256 `c75f1cdf6621fac32c7b712a5d2dc1937b7ce9cbbb5439925de0013aa6347988`. No se afirma que todos los metadatos anteriores se hayan restaurado.

## 9. Paso 7 — Validación independiente en el SIEM

La **tercera alerta** (`1791645056.445431`) registró:

```text
syscheck.event: modified
syscheck.mode: realtime
size_before: 77
size_after: 34
sha256_before: f740ee5bb8732fb79dc3ef99b3c75027660480f41e655ca9c290cdeca9abfdef
sha256_after: c75f1cdf6621fac32c7b712a5d2dc1937b7ce9cbbb5439925de0013aa6347988
```

El diff mostró la eliminación de la línea simulada; el inode reportado era `527576`. Esta alerta corrobora desde Wazuh el estado recuperado observado localmente.

## 10. Cronología y calidad de tiempos

| Hito | Marca recogida (tal como fue observada) |
|---|---|
| Baseline previo en Linux | `2026-10-10T16:52:42,057973442+00:00` |
| Comando de creación en Linux | `2026-10-10T16:53:23,401879906+00:00` |
| Modificación (`mtime`) en Linux | `2026-10-10 16:53:23.564907424 +0000` |
| Alerta de creación en Wazuh | `2026-10-10T14:53:21.605+0000` |
| Alerta de modificación en Wazuh | `2026-10-10T14:53:21.745+0000` |
| Verificación final en Linux | `2026-10-10T17:10:57,966252554+00:00` |
| Alerta de recuperación en Wazuh | `2026-10-10T15:10:56.026+0000` |

**Problema pendiente:** la consola Linux indicó `+00:00` pero difería aproximadamente dos horas de las marcas del manager. No se comprobó la sincronización entre ambas fuentes; por tanto **no** se calculan latencia de detección, MTTD o MTTR. No reinterpretar ni corregir las marcas originales sin evidencia.

## 11. Cierre y límites

**Verificado:** archivo creado, alterado, detectado, restaurado y nuevamente detectado. Los hashes inicial/final coinciden localmente y en Wazuh.

**No demostrado:** ataque real, identidad adversaria, necesidad de contención, erradicación de malware, restauración de metadatos completos o integridad probada del snapshot VMware.

El ejercicio se cierra como **simulación autorizada con recuperación del contenido comprobada**. Véanse [lecciones aprendidas](../docs/IR-001-lessons-learned.md) y [registro de evidencias](../evidence/evidence-manifest.md). Los tres JSON originales se aportaron durante la investigación, pero **no están incluidos como archivos en este paquete público**.
